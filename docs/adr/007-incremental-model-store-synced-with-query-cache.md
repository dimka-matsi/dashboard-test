# ADR-007. Инкрементальная доменная модель, синхронизированная с кэшем запросов

**Статус:** принято · **Этап:** step/3

## Контекст

Требования этапов 2 и 3 конфликтуют при наивной реализации: «агрегация считается один раз
и мемоизируется» и «пересчёт агрегатов только для затронутого узла и предков». Если модель —
`useMemo` от данных запроса, любой патч, записанный в кэш, меняет ссылку данных и запускает
полный пересчёт. Нужен способ применять патч инкрементально и при этом не расходиться с кэшем,
из которого происходят фоновые refetch.

## Решение

`OrgModelStore` (`entities/org/store/org-store.ts`) — тонкий слой между кэшем и моделью:

1. **`modelFor(snapshot)`** строит модель один раз на ссылку снимка и кэширует по ней.
2. **`applyPatch(patch)`**:
   - проверяет `seq` относительно версии снимка (`stale` / `gap` / применить);
   - `applyNodeChanges` заменяет только изменённые узлы и пересчитывает агрегаты **только по
     цепочке предков** (`aggregateNode` — та же функция, что в полном пересчёте), остальные
     объекты сохраняют ссылки;
   - записывает новый снимок в кэш через `setQueryData` и запоминает ссылку, которую кэш реально
     сохранил (structural sharing может вернуть другую).
3. **Самовосстановление.** Следующий refetch, вернувший то же состояние, не меняет ссылку —
   модель не пересобирается. Если состояние разошлось (пропущенный патч), ссылка новая, и модель
   честно перестраивается из снимка. Патчи — ради скорости, снимки — ради корректности.
4. **Карта подсветки** (`flashes`): для реально изменившихся ячеек хранится время изменения;
   ячейка получает новый `key` и CSS-анимация затухания перезапускается без таймеров в React.
5. **Мемоизация UI.** Строка таблицы сравнивает ссылки `node` и `aggregate` из модели:
   после патча перерисовываются только строки затронутых узлов и предков.

## Альтернативы

- **Внешний стор с `useSyncExternalStore` вместо записи в кэш.** Тогда кэш запроса и модель
  живут раздельно, и первый же фоновый refetch затирает патчи полной пересборкой.
- **Хранить модель в самом кэше запроса.** Structural sharing работает только с plain-объектами,
  `Map` в модели каждый раз получал бы новую ссылку — мемоизация ломается.
- **Полный пересчёт на каждый патч.** O(n) на ~60 узлов дёшево, но требование явно про
  инкрементальность, и на больших структурах это единственный масштабируемый путь.

## Последствия

- `+` O(глубина · ветвление) на патч; ноль лишних перерисовок незатронутых строк.
- `+` Инвариант «инкрементально = полный пересчёт» закреплён тестом на случайных патчах.
- `−` Два источника изменений модели (снимок и патчи) требуют дисциплины версий — она
  сосредоточена в одном классе и покрыта тестами.
