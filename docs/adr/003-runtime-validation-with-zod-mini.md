# ADR-003. Валидация ответов API через zod/mini

**Статус:** принято · **Этап:** step/1

## Контекст

Схема ответа API должна валидироваться на клиенте, невалидный ответ — ошибка. Схема нужна и серверу
(валидация входящих запросов, JSON Schema для structured output в AI-поиске). Есть бюджет
production-сборки: ≤ 200 КБ gzip.

## Решение

`zod` v4 в варианте **`zod/mini`** — функциональный tree-shakeable API того же ядра.

Измерения на пробной сборке (gzip, только вклад библиотеки поверх React):

| Вариант        | КБ gzip |
| -------------- | ------- |
| `zod` (полный) | ~23     |
| `zod/mini`     | ~5      |
| `valibot`      | ~1.4    |

`zod/mini` выбран как компромисс между размером и узнаваемостью: у `zod` самая широкая экосистема,
`z.toJSONSchema()` есть в ядре и используется для описания инструмента LLM, а разница с `valibot`
в 3–4 КБ некритична при бюджете 200 КБ.

Русская локаль сообщений (`z.locales.ru()`) включается на клиенте, чтобы блок «Подробности»
в состоянии ошибки был читаем.

## Альтернативы

- **Полный `zod`.** Удобный chain-API, но четверть бюджета сборки уходит на валидацию.
- **`valibot`.** Минимальный размер, но меньше знакомых проверяющему паттернов; отдельная экосистема
  для JSON Schema.
- **Ручные type guards.** Нулевой размер, но нет сообщений об ошибках и второй источник правды
  относительно типов.

## Последствия

- `+` Одна схема даёт тип, валидацию и JSON Schema.
- `−` Функциональный API (`z.nullable(z.string())` вместо `z.string().nullable()`) непривычен;
  задокументирован в `packages/contracts`.
