# ADR-002. TanStack Query как слой кэширования запросов

**Статус:** принято · **Этап:** step/1

## Контекст

Нефункциональные требования: кэширование ответов, stale time 5 секунд, stale-while-revalidate,
отсутствие лишних запросов, отмена при размонтировании, инвалидация кэша только при реальном
изменении данных, состояния загрузки/ошибки/пустого ответа.

## Решение

Использовать `@tanstack/react-query` v5 c явной конфигурацией (`apps/web/src/app/query-client.ts`):

- `staleTime: 5000` — повторный монтаж или фокус окна внутри 5 секунд не порождает запрос;
- `queryFn` получает `signal` и передаёт его в `fetch` — когда последний подписчик размонтирован,
  запрос отменяется;
- `structuralSharing: true` — если ответ структурно равен предыдущему, ссылка на данные не меняется,
  `useMemo` и `memo` ниже не пересчитываются. Вместе с ETag/304 на сервере это даёт «инвалидацию
  только при реальном изменении»;
- `retry` — только для сетевых сбоев и 5xx; невалидный ответ и 4xx не повторяются;
- `refetchOnWindowFocus` / `refetchOnReconnect` — фоновая ревалидация без мигания UI.

Библиотека — единственная точка запросов; сама валидация ответа схемой живёт в `shared/api/http.ts`.

## Альтернативы

- **Собственный мини-SWR (fetch + Map + таймеры).** Показал бы понимание механики, но это ~200 строк
  с тонкими багами (дедупликация параллельных запросов, гонки при отмене, GC), а оценивается
  в задании не он, а доменная модель и live-обновления. Механика описана в `docs/architecture.md`.
- **SWR (vercel).** Компактнее, но слабее в точечной записи в кэш (`setQueryData`), которая нужна
  для применения патчей без рефетча.
- **Zustand/Redux + ручной fetch.** Состояние сервера — не клиентское состояние; инструменты
  для него хуже подходят для stale-while-revalidate.

## Последствия

- `+` ~10 КБ gzip за дедупликацию, кэш, ретраи, отмену и devtools.
- `+` Патчи live-обновлений пишутся в кэш через `setQueryData`, поэтому фоновый refetch,
  вернувший то же состояние, не меняет ссылку и не перестраивает модель (см. ADR-005).
- `−` Ещё одна зависимость с собственной ментальной моделью (query keys, observers).
