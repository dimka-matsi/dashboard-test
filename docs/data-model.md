# Модель данных

## Узел орг-структуры

`GET /api/org-tree` возвращает **плоский массив** узлов (`packages/contracts/src/org-node.ts`):

| Поле          | Тип              | Ограничения                           |
| ------------- | ---------------- | ------------------------------------- |
| `id`          | `string`         | непустой, уникальный                  |
| `name`        | `string`         | 1–200 символов                        |
| `parentId`    | `string \| null` | `null` — корень (дивизион)            |
| `headcount`   | `int`            | ≥ 0, собственная численность узла     |
| `budget`      | `number`         | ≥ 0, рубли, собственный бюджет узла   |
| `performance` | `number`         | 0–100, собственная эффективность узла |
| `updatedAt`   | `string`         | ISO-8601 (`2026-09-14T10:00:00.000Z`) |

Метрики узла — **собственные**, без потомков. У дивизиона и отдела они ненулевые (управленческий
персонал и его бюджет), поэтому агрегат узла = собственные значения + значения всех потомков.

Валидация на клиенте: `z.safeParse(OrgTreeResponseSchema, json)`. Один невалидный элемент делает
невалидным весь ответ — частично корректные данные показывать опаснее, чем не показывать.

## Дерево

Плоский массив превращается в индекс `OrgTree` (`apps/web/src/entities/org/model/build-org-tree.ts`):

```ts
interface OrgTree {
  nodes: Map<id, OrgNode>; // O(1) доступ
  children: Map<id, id[]>; // дети, отсортированы по имени (Intl.Collator 'ru', numeric)
  roots: id[]; // parentId === null
  depth: Map<id, number>; // 1 — дивизион, 2 — отдел, 3 — команда
  order: id[]; // pre-order обход: порядок строк таблицы «как в дереве»
  maxDepth: number;
}
```

Алгоритм: один проход для индекса и группировки детей, сортировка детей, итеративный DFS для
глубины и порядка. Сложность O(n log n) из-за сортировки.

### Проверки целостности

Схема гарантирует форму каждого узла, но не согласованность массива. Ошибки `OrgTreeError`:

| Код              | Условие                                        |
| ---------------- | ---------------------------------------------- |
| `duplicate-id`   | два узла с одним `id`                          |
| `missing-parent` | `parentId` указывает на отсутствующий узел     |
| `self-parent`    | `parentId === id`                              |
| `cycle`          | после DFS от корней остались непосещённые узлы |

Любая из них переводит экран в состояние ошибки — так же, как невалидная схема.

## Уровни

| depth | Название  |
| ----- | --------- |
| 1     | Дивизион  |
| 2     | Отдел     |
| 3     | Команда   |
| n > 3 | Уровень n |

## Эффективность: бакеты индикатора

| Значение | Бакет    | Цвет    |
| -------- | -------- | ------- |
| < 50     | `low`    | красный |
| 50–74    | `medium` | жёлтый  |
| ≥ 75     | `high`   | зелёный |
