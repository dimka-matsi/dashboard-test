# Журнал использования AI в разработке

Хронологический журнал того, как применялись AI-инструменты. Из него собирается раздел
«AI в разработке» в README. Записи добавляются по мере работы, а не задним числом.

Инструмент: **Claude Code** (агентная сессия в облачном контейнере, модель семейства Claude).
Роль человека: постановка задачи, разбор задания, принятие архитектурных решений, ревью.

## Подготовка

- По PDF задания составлен разбор скрытых критериев оценки и список неоднозначностей
  (трактовка «второй уровень открыт», семантика клика/двойного клика в сортировке, формат бюджета
  с неразрывным пробелом, нулевой headcount во взвешенном среднем).
- Прежде чем выбрать стек, AI собрал пробный Vite-бандл и измерил gzip-вклад библиотек:
  React 19 + ReactDOM ≈ 68 КБ, styled-components ≈ 11 КБ, TanStack Query ≈ 10 КБ,
  полный zod ≈ 23 КБ против zod/mini ≈ 5 КБ. Это определило выбор `zod/mini` (ADR-003).
- Проверена совместимость свежих мажоров: TypeScript 7 (latest в npm) не поддерживается
  typescript-eslint, поэтому зафиксирован TypeScript 5.9.

## Step 1 — foundation

**Сгенерировано AI:** скаффолд монорепозитория (npm workspaces, tsconfig, ESLint flat config,
Prettier, Vitest projects), пакет контрактов на zod/mini, mock-сервер на `node:http`
(генератор данных с seed, ETag/304, сценарии `empty|error|invalid|slow`), слой запросов
(`fetchJson` + TanStack Query), построение дерева с проверкой целостности, компоненты дерева и
состояний, тесты.

**Переделано в ходе работы (и почему):**

- Классы ошибок сначала использовали parameter properties (`constructor(readonly code: ...)`);
  `tsc` с `erasableSyntaxOnly` их запрещает — переписаны на явные поля. Опция оставлена намеренно:
  код должен быть исполним любым транспилятором, который просто стирает типы.
- Первый вариант `useOrgTree` показывал ошибку при любом сбое refetch, даже если данные уже были
  на экране. Заменено на «данные остаются, сверху предупреждение» — ошибка фонового обновления не
  должна прятать рабочий дашборд.
- Цвет индикатора эффективности предполагалось интерполировать в CSS из значения; заменено на
  бакеты через `data-bucket`, чтобы styled-components не генерировал класс на каждое значение.

**Проверялось руками/тестами:** контракт (валидные/невалидные узлы), генератор (≥40 узлов,
3 уровня, детерминизм), HTTP (ETag → 304, сценарии), дерево (сортировка ru, циклы, сироты),
компонент Dashboard (загрузка → дерево, раскрытие, пусто, ошибка, невалидный ответ).

## Step 2 — core

**Сгенерировано AI:** агрегация (`aggregateNode` / `computeAggregates`), модель `OrgModel`,
конвейер строк таблицы (`buildRows` → `filterRows` → `sortRows`), компоненты таблицы и панели,
переключатель режимов и split-view через `matchMedia`, синхронизация выделения между таблицей и
деревом, форматирование (`Intl.NumberFormat('ru-RU')`), тесты.

**Решения, принятые в ходе работы (и почему):**

- Взвешенное среднее хранится как пара «числитель/знаменатель», а не как число: иначе родитель
  усреднял бы средние детей — математически неверно.
- Одиночный клик по уже выбранному столбцу намеренно ничего не делает: двойной клик приходит
  после двух одиночных, и «клик переключает направление» дал бы результат, зависящий от скорости
  клика. Обратный порядок — только двойным кликом (или Shift+Enter), сброс — кнопкой.
- Рассматривался вариант «предки выбранного узла всегда раскрыты» как производное состояние
  без эффекта. Отклонён: пользователь не смог бы свернуть ветку с выбранным узлом. Раскрытие
  делается один раз при смене выбора.
- Панели на узком экране не размонтируются, а скрываются атрибутом `hidden`, чтобы при
  переключении не терять раскрытие дерева, фильтр и сортировку.
- Средняя эффективность форматируется через `Intl` с одним знаком после запятой («67,6»),
  а не `toFixed`, чтобы разделитель был русским.

**Проверялось тестами:** агрегаты (лист, отдел, дивизион, взвешенность, ноль сотрудников,
инвариант «узел = собственное + дети», `aggregateNode` = полный пересчёт), строки/фильтр/
сортировка (стабильность, `null` в конце, локаль), формат бюджета с неразрывным пробелом,
дебаунс 250 мс с fake timers, компонент таблицы (клик/двойной клик/сброс, фильтр с дебаунсом,
выбор строки), синхронизация таблицы и дерева в обоих режимах.

## Step 4 — bonus

**Сгенерировано AI:** Dockerfile сервера и клиента (multi-stage, контекст — корень монорепо),
шаблон nginx (gzip, прокси `/api` и `/ws` с upgrade, immutable-кэш ассетов, SPA-fallback),
`docker-compose.yml` с конфигом через `.env`, скрипт проверки бюджета сборки, GitHub Actions
CI, контракт фильтра поиска, разбор правилами, разбор моделью через `@anthropic-ai/sdk`
(structured output), сервис с кэшем, клиентская интеграция (чипы, источник, fallback), тесты,
ADR-008.

**Решения и переделки в ходе работы:**

- Перед написанием кода вызова модели был прочитан справочник по Claude API из набора
  инструментов: он предписывает официальный SDK вместо `fetch`, канонический параметр
  `output_config.format` для structured output и модель `claude-opus-5` по умолчанию.
  JSON Schema фильтра написана руками (описания полей, без числовых ограничений), а границы
  проверяет zod-схема контракта уже на ответе.
- Регулярные выражения для русских слов не могут опираться на `\b` (в JS это ASCII-граница):
  границы слов заданы через `(?<!\p{L})` с флагом `u`.
- Server-side fallback на другую модель при отказе (beta-параметр) намеренно не добавлен:
  в среде разработки нет ключа, проверить параметр невозможно, а отказ модели уже обрабатывается
  переходом к правилам.
- Ручная сортировка пользователя имеет приоритет над сортировкой из AI-фильтра — иначе клик
  по заголовку «не работал» бы, пока активен фильтр.
- Docker-демон в среде разработки недоступен: compose-файл проверен `docker compose config`,
  сборка образов — на стороне пользователя.

**Проверялось тестами:** правила (формулировки на русском и английском, единицы измерения,
«топ N», предок), сервис (приоритет модели, fallback, кэш, пустой фильтр), LLM-парсер с
подменённым клиентом (параметры запроса, ответ вне схемы, отказ, ошибка API), маршрут `POST`
(200/400), применение фильтра на клиенте, интеграция строки поиска (запрос уходит на сервер,
чипы, fallback при `null` и при ошибке, одно слово не отправляется).

## Редизайн интерфейса (после step/4)

**Задача.** Пользователь показал референсы (интерфейс Box с боковой панелью и AI-поиском,
график Box AI, схему процесса) и попросил такой же уровень визуальной проработки.

**Сгенерировано AI:** система токенов со светлой и тёмной темой (`lightTheme` / `darkTheme`,
переключатель запоминается в localStorage, системная настройка по умолчанию), боковая панель
с режимами просмотра «Дерево / Таблица / Вместе», переключателями live и темы и меню
демо-сценариев, командная строка поиска в шапке с бейджем источника, панель KPI-плиток
и график средней эффективности по дивизионам, иконки уровней в дереве, подсветка найденных
узлов и приглушение остальных, метр эффективности в таблице, набор SVG-иконок.

**Как принимались визуальные решения:**

- Перед графиком прочитан гайд по визуализации из набора инструментов: одна серия — один цвет
  (палитра проверена скриптом-валидатором на светлой и тёмной поверхности), столбики не толще
  24 px со скруглённым торцом у данных, значения на торцах, подсказка по наведению, без второй
  оси; для KPI — stat-плитки с пропорциональными цифрами, а не столбики; статусные цвета
  эффективности только рядом с числом.
- Высота столбиков и заливка метра заданы transient-пропом styled-components (класс на целое
  значение процента), потому что inline-стили запрещены заданием.
- Поиск поднят из панели таблицы в шапку и стал единым состоянием: таблица фильтруется,
  дерево подсвечивает те же узлы и раскрывает их предков.
- Найдено скриншотами и исправлено: значение бюджета не помещалось в плитку при 1440 px,
  последняя колонка таблицы обрезалась при ширине 16 %, кнопка devtools перекрывала таблицу
  (теперь включается адресом `?devtools=on`).

**Тесты:** сводка (`summarize`), плюрализация и компактный формат сумм, плитки и график
в Dashboard, подсветка поиска в дереве, обновление плитки по live-патчу; тесты таблицы и
поиска переведены на общий харнес «строка поиска + таблица».
