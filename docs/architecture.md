# Архитектура

## Общая картина

```
┌──────────────────────────┐        GET /api/org-tree (ETag/304)        ┌──────────────────────┐
│        apps/web          │ ◄───────────────────────────────────────── │     apps/server      │
│  React 19 · Vite · SC    │        WS /ws: patch / resume / resync     │ node:http · ws       │
└──────────────────────────┘ ◄───────────────────────────────────────── └──────────────────────┘
              ▲                                                                     ▲
              └──────────────── packages/contracts (zod/mini-схемы, типы) ──────────┘
```

Клиент и сервер разделяют пакет контрактов: одну и ту же схему сервер использует для валидации
входящих данных, а клиент — для проверки ответов. Изменение контракта ломает typecheck на обоих концах.

## Слои клиента (`apps/web/src`)

Структура «сверху вниз»: слой может импортировать только то, что ниже него.

| Слой     | Каталог     | Ответственность                                                                 |
| -------- | ----------- | ------------------------------------------------------------------------------- |
| app      | `app/`      | точка входа, провайдеры (QueryClient, тема, глобальные стили), конфиг кэша      |
| widgets  | `widgets/`  | композиция страницы: `Dashboard` собирает шапку, панели и состояния экрана      |
| features | `features/` | пользовательские сценарии: дерево (`org-tree`), таблица, live-обновления, поиск |
| entities | `entities/` | доменная модель орг-структуры: индекс дерева, агрегаты, запрос, описание ошибок |
| shared   | `shared/`   | переиспользуемое без домена: HTTP-клиент с валидацией, конфиг, UI-примитивы     |

Абсолютные импорты через алиас `@/` (tsconfig `paths` + `resolve.alias` в Vite).

## Поток данных: от API до UI

```
fetch(url, { signal }) ──► fetchJson(): HTTP-статус → JSON → z.safeParse(schema)
        │                          │ невалидно → ApiError('invalid-response')
        ▼                          ▼
TanStack Query cache  (staleTime 5 с, structural sharing, retry только для network/5xx)
        │  data: OrgNode[]  — ссылка меняется только при реальном изменении данных
        ▼
buildOrgTree(data)  (useMemo по ссылке data): Map узлов, дети, корни, глубина, порядок обхода
        │  ошибка целостности (дубль, сирота, цикл) → OrgTreeError → состояние «ошибка»
        ▼
useOrgTree(): loading | error | empty | ready
        ▼
Dashboard → OrgTreePanel → TreeView → TreeNodeItem (memo)
```

### Почему запросы не дублируются и не «дёргают» UI

1. **Один запрос на ключ.** Все подписчики ключа `['org-tree', { scenario }]` делят один in-flight
   запрос; повторный монтаж компонента внутри `staleTime` (5 с) вообще не ходит в сеть.
2. **Отмена.** `queryFn` передаёт `signal` в `fetch`; если все подписчики размонтировались до ответа,
   запрос отменяется.
3. **304 без тела.** Сервер отдаёт `ETag` и `Cache-Control: no-cache`; браузер сам ставит
   `If-None-Match`, и пока данные не менялись, ответ — `304` без тела.
4. **Structural sharing.** Если содержимое ответа совпало с кэшем, TanStack Query сохраняет прежнюю
   ссылку. `useMemo` дерева и `memo` узлов не пересчитываются — «инвалидация только при реальном
   изменении данных» выполняется на уровне ссылок, а не сравнений в компонентах.

## Состояния экрана

`useOrgTree` сводит состояние запроса и результат построения дерева к четырём вариантам:

- `loading` — первый запрос ещё не завершён;
- `error` — запрос упал **и данных нет** (сеть, HTTP, невалидный ответ, нарушение целостности);
- `empty` — сервер вернул `[]`;
- `ready` — дерево построено; если фоновое обновление упало, данные остаются, а сверху появляется
  предупреждение (`refetchError`).

Каждое состояние проверяется без правки кода через `?scenario=slow|empty|error|invalid`.

## Раскладка экрана

```
┌──────┬────────────────────────────────────────────────────────────────┐
│ rail │ TopBar: бренд · командная строка поиска (AI) · соединение · ↻ │
│      ├────────────────────────────────────────────────────────────────┤
│ реж. │ KpiStrip: Сотрудников · Бюджет · Средняя эффективность ·       │
│ live │           Подразделений · график по дивизионам                 │
│ тема ├───────────────────────────┬────────────────────────────────────┤
│ демо │ OrgTreePanel              │ AnalyticsTablePanel                │
└──────┴───────────────────────────┴────────────────────────────────────┘
```

- **Rail** (`widgets/dashboard/Rail.tsx`): режим просмотра «Дерево / Таблица / Вместе»
  (split доступен от 1280 px), включение live-обновлений, тема, меню демо-сценариев.
- **TopBar**: единая строка поиска (`features/search/use-search.ts`) — её состояние читают
  и таблица (фильтр), и дерево (подсветка совпадений, раскрытие предков).
- **KpiStrip**: сводка компании (`entities/org/model/summary.ts`) и график средней
  эффективности по дивизионам; плитки подсвечиваются при live-патчах, как ячейки таблицы.
- **Тема**: `lightTheme` / `darkTheme` с одинаковой структурой токенов
  (`app/styles/theme.ts`); `ThemeModeProvider` берёт системную настройку и запоминает выбор
  пользователя в localStorage.

## Таблица: производное состояние

```
OrgModel ──buildRows──► rows (порядок дерева)
                          │  useDebouncedValue(query, 250 мс)
                          ▼
                       filterRows ──► sortRows(sort) ──► AnalyticsTable
```

Каждый шаг в своём `useMemo`: смена фильтра не пересобирает строки, смена сортировки не
перефильтровывает. Пустой фильтр и отсутствие сортировки возвращают входной массив той же ссылкой.

Семантика сортировки: клик — по возрастанию по новому столбцу, повторный клик по тому же столбцу
ничего не меняет, двойной клик — обратный порядок (см. ADR-005), сброс — кнопкой.

## Выделение и режимы просмотра

`selectedId` живёт в `Dashboard` и передаётся в обе панели. Клик по строке таблицы выделяет узел
в дереве: `OrgTreePanel` раскрывает предков (`ancestorsOf`), узел прокручивается в видимую область.
Клик по узлу дерева подсвечивает строку таблицы.

От 1280 px панели показываются рядом (split-view), на узких экранах — переключатель
«Дерево / Таблица» в шапке; выбор строки на узком экране переключает на дерево. Обе панели
остаются смонтированными (`hidden`), чтобы раскрытие ветвей, фильтр и сортировка не терялись.

## AI-поиск

```
ввод ──250 мс──► filterRows(text)                     (мгновенный текстовый фильтр)
  │
  └─ фраза ≥ 2 слов или число ──500 мс──► POST /api/search/parse ──► сервер:
                                                               1. модель (structured output) при наличии ключа
                                                               2. правила (rules.ts)
                                                               3. { filter: null }
        ответ валидируется SearchParseResponseSchema ──► applySearchFilter(rows, filter, tree)
        null / ошибка ──► остаётся текстовый фильтр
```

Ключ модели живёт только на сервере (`ANTHROPIC_API_KEY`); без него сервер отвечает по правилам.
Подробности — ADR-008.

## Развёртывание

```
docker compose up --build
┌───────────────────────── web (nginx:alpine) ────────────────────────┐
│  /            статика Vite (gzip, immutable-кэш для /assets)         │
│  /api/*  ───► proxy_pass http://server:3001                          │
│  /ws     ───► proxy_pass + Upgrade (WebSocket), таймаут 1 ч          │
└──────────────────────────────────────────────────────────────────────┘
                                   │
┌───────────────────────── server (node:22-alpine) ────────────────────┐
│  один файл dist/index.js (esbuild): http + ws + zod + Anthropic SDK   │
│  конфиг из переменных окружения (.env в корне через compose)         │
└──────────────────────────────────────────────────────────────────────┘
```

Оба Dockerfile используют корень репозитория как контекст (общий lockfile npm workspaces).
Сборка клиента падает, если gzip-размер JS+CSS превышает 200 КБ (`scripts/check-bundle-size.mjs`,
он же запускается локальным `npm run build`).

## Стили

styled-components v6 c типизированной темой. Inline-CSS запрещён линтером
(`react/forbid-dom-props` для `style`). Данные с большим числом значений (эффективность 0–100)
отображаются через бакеты и `data`-атрибуты, чтобы не порождать класс на каждое значение.
`prefers-reduced-motion` уважается глобально в `GlobalStyle`.

## Сервер (`apps/server/src`)

| Модуль            | Назначение                                                               |
| ----------------- | ------------------------------------------------------------------------ |
| `config.ts`       | конфигурация из переменных окружения (`.env` в корне подхватывается сам) |
| `data/`           | детерминированный генератор (mulberry32 + каркас структуры на 56 узлов)  |
| `state.ts`        | состояние в памяти, версия (`seq`), ETag                                 |
| `http/handler.ts` | маршруты `GET /api/org-tree`, `GET /api/health`, сценарии, ETag → 304    |

Разделы про live-обновления, агрегацию и AI-поиск дополняются на соответствующих этапах.
